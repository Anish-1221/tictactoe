About this task

Same engine as Task 4 (paranoid alpha-beta, three players, three in a row), on boards from 3×3 up to 10×10. A 10×10 board has about 100 possible moves per turn, so a few plies of full search is already too much for a browser. What keeps it manageable:

  • Candidate radius: only empty cells within this distance of an existing mark are considered. On 10×10 with radius 2 that cuts the moves per turn from about 95 to about 40.
  • Move ordering: wins first, then blocks, then cells with the most open paths, so alpha-beta can cut early.
  • Depth limit: past this depth the board is scored directly. Each open line is worth (marks in it)3, so two in a line counts for much more than two scattered marks.
  • Node ceiling: if one move's search goes past this many nodes, it stops and returns the best move found so far instead of running the browser out of memory.

Limits

With radius 2 and the default 400,000-node ceiling, depth 4 finishes on every board size up to 10×10 (peak around 75,000 nodes for one move, under two seconds per game on 10×10). Depth 5 hits the ceiling from 6×6 up. Switching to maxn hits it at depth 4 on the large boards.
