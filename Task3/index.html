What this task shows

Both agents use the same depth-limited alpha-beta search. When both are set to depth 9 they search to the end of the game and play perfectly, and every game is a draw. That is the correct result for 3×3 tic-tac-toe, not a bug, which is why the depth controls are here: lowering one agent's depth is what produces wins and losses to count.

Two details were needed to make a batch of N games meaningful. First, the agents are deterministic, so without intervention all N games would be move for move identical. The search therefore picks at random among moves that share the best exact value, which keeps play optimal while letting games differ. Second, the root search deliberately does not prune between its own candidate moves, because under pruning a score equal to alpha is only an upper bound and treating it as a tie would let a perfect agent choose a losing move.

Below depth 9 the search stops early and scores the position with a heuristic: lines still open to a player, weighted by the square of how many marks the player already has in them, minus the same for the opponent.
