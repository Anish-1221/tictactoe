What this task shows

Alpha-beta pruning returns a move of exactly the same value as plain minimax but visits far fewer positions. From an empty board the unpruned search explores 549,946 nodes. Alpha-beta with the moves taken in board order needs 20,866, and with the open paths ordering described below it needs 6,347, which avoids 98.8% of the work. All three figures are reported above on every move so the saving is visible rather than asserted.

The pruning rule: during the search each side tracks the best score it can already guarantee elsewhere, called alpha for the maximising player and beta for the minimising one. When alpha >= beta the player choosing at the parent node would never allow play to reach the current position, so the remaining sibling moves cannot affect the outcome and are abandoned. Each abandonment is counted as a cutoff.

Which move to try first

How much alpha-beta prunes depends on the order the moves are tried in: finding a strong move early tightens the bounds sooner. The search here tries first the cell with the most possible paths still open, meaning the lines through that cell the opponent has not yet blocked. On an empty board the centre lies on 4 lines, each corner on 3 and each edge on 2, so the centre is searched first. The ordering changes only how much work is done, never the value of the move.

The machine plays perfectly, so the best you can get is a draw.
